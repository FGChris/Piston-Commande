# Validation avant le premier lot

Le dossier documentaire a été demandé, puis le Boss a explicitement validé le lot 1 : connexion, isolation des garages et véhicule sur source de test. Aucun achat de service ni intégration réelle n’est autorisé par cette validation. Les questions restantes concernent les lots suivants.

## Questions groupées à présenter au Boss

| Sujet | Recommandation | Ce que la réponse débloque |
|---|---|---|
| Plan technique et lot 1 | Next.js/TypeScript/PostgreSQL ; socle, isolation et identification avec source de test explicite | Premier lot de code |
| Données de test | Jeux synthétiques clairement séparés ; jamais de résultat présenté comme réel | Développement sans accès fournisseur |

| Marques et délais | LUCAS filtration, puis Mecafilter DASIR ; exceptions décidées par famille, urgence confirmée par le vendeur | Classement des offres |

Les réponses oui/non sans questions d’origine ne bloquent pas la préparation du socle, mais ne peuvent autoriser aucune fonction supplémentaire. Demander les questions originales avant de leur attribuer un sens.

## À vérifier avant chaque connecteur réel

Accès existant, droits d’automatisation et conservation, MFA/session, capacités API effectivement disponibles, quotas et coût. L’API Henrri est mentionnée dans le brief mais non vérifiée. Aucun secret à communiquer dans les documents ou le chat. Un compte donnant accès au portail ne prouve pas un droit d’API.

## Avant usage client

Identité du garage, fiscalité et réglages tarifaires, arrondis, libellés et mentions, droits des opérateurs, durée des liens, signature, confidentialité, sauvegarde/restauration et procédure de panne. Tester le parcours complet dans un navigateur mobile et avec les rôles réels. Aucun envoi, commande ou document juridique réel pour une simple démonstration.
